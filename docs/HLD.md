# CaseTrail — High-Level Design (HLD)

Companion docs: `LLD.md` (module internals, data formats, APIs) · `DECISIONS.md` (stack choices and trade-offs) · `PLAN.md` (goals, team, rubric).

---

## 1. Goals and non-goals
**Goals**
1. Given a judgment (or case facts), return the top-K most similar earlier Supreme Court judgments (**PCR**).
2. Predict the applicable IPC sections (multi-label over 100 statutes) with confidence scores (**LSI**).
3. Explain every result: keyword (BM25), meaning (neural), authority (PageRank/HITS) contributions and matched passages.
4. Be evaluated on IL-TUR with the benchmark's metrics and compared with its published baselines.
5. Run the full demo **on a laptop CPU, offline**, with interactive latency.

**Non-goals**
- Legal advice, answer generation as the main output, or multi-court coverage beyond the dataset.
- Serving many concurrent users, cloud deployment, authentication.
- Training huge models (budget: free Kaggle T4 GPUs + a 4 GB laptop GPU).

## 2. Quality targets (initial; confirm after P2/P5)
| Attribute | Target |
|---|---|
| PCR quality | µF1@K close to or above the IL-TUR baseline (39.15%) |
| LSI quality | macro-F1 close to or above LeSICiN (28.08%) |
| Search latency (warm, laptop CPU) | ≤ 1 s median for PCR + LSI together; ≤ 2 s p95 |
| Student model size | ≤ 30 MB INT8 (vs teacher size, reported) |
| Index build | ≤ 10 min on the laptop |
| Reproducibility | every number regenerated by `scripts/`; fixed seed 13 |
| Offline | no network calls at query time |

## 4. Components
| # | Component | Responsibility | Inputs → Outputs |
|---|---|---|---|
| C1 | **Data loader** (`data.py`) | load IL-TUR pcr/lsi splits, statute descriptions; one canonical in-memory format | parquet/HF files → dicts of documents, relevance, labels |
| C2 | **Text pipeline** (`text/`) | normalise, tokenise, stop words, keep legal section references as tokens | raw text → token lists |
| C3 | **Inverted index** (`index/`) | dictionary + postings with tf, doc lengths; save/load | token lists → index on disk |
| C4 | **Lexical retrieval** (`retrieval/`) | BM25, tf-idf cosine, long-query reduction, paragraph-level scoring | query tokens → scored candidates |
| C5 | **Link analysis** (`graph/`) | build graphs; PageRank, HITS | documents + statute links → node scores |
| C6 | **Neural retrieval** (`neural/`) | student bi-encoder (INT8 ONNX) encodes chunks; dense search; distilled reranker | text → vectors → scored candidates |
| C7 | **Fusion** (`fusion/`) | combine lexical, neural, graph signals (RRF / weighted, tuned on dev) | per-signal scores → final ranking + breakdown |
| C8 | **Statute classifiers** (`classify/`, `neural/statute_attention.py`) | NB, Rocchio, kNN, neural cross-attention | document → statute probabilities |
| C9 | **Engine** (`search.py`) | one entry point: `search(text, system, k)` and `predict_statutes(text, method)`; returns results + explanation | text → JSON-ready dict |
| C10 | **Evaluation** (`eval/`, `scripts/`) | metrics, significance, ablations, plots | runs + qrels/labels → `results/` |
| C11 | **API** (`api/`) | HTTP endpoints for the demo; reads engine + `results/` | HTTP ↔ engine |
| C12 | **Frontend** (`frontend/`) | Waypoint-style UI; display only | API JSON → pages |

## 5. Data flow
### 5.1 Offline (build once, rebuilt by scripts)
1. `download_data.py` → `data/raw/` (gated download, user logs in).
2. `build_index.py` → C2 + C3 over all candidate pools (per split) → `indexes/pcr_<split>/`.
3. `build_graph.py` → C5 graphs + PageRank/HITS scores → `indexes/graph/`.
4. Kaggle notebook → teacher + student training → export ONNX INT8 → `models/student_int8.onnx` (copied to laptop).
5. `encode_corpus.py` → student vectors for every candidate chunk → `indexes/dense_<split>.npy`.
6. `train_classifiers.py` → NB / Rocchio / kNN models (+ neural statute model from Kaggle) → `models/lsi_*`.
7. `tune_*.py` on **dev** → `results/tuned_params.json`.

### 5.2 Online (one query)
1. Text → C2 tokens + C6 chunk vectors (parallel-safe, CPU).
2. C4 BM25 top-200 (with query reduction) and C6 dense top-200 over the **same split's** candidate pool.
3. C7 fusion of candidates (+ PageRank prior) → optional distilled reranker on top-50 → top-K.
4. C8 statute probabilities (chosen method) → top statutes above the tuned threshold.
5. C9 assembles the explanation: per-signal scores, matched passages, query terms with df/idf, graph scores, timings.

### 5.3 Evaluation
Scripts run every system on dev (tuning) and test (final) and write long-format CSVs (`task, system, split, metric, value, n`).

## 6. Deployment (demo)
- Laptop only: `uvicorn api.main:app` on `127.0.0.1:8000`, `next start` (or `next dev`) on `:3000`.
- All artifacts loaded once at API start-up (warm-up query on start). No database, no external services, no internet at query time.
- Training happens on Kaggle; only exported weights come back.

## 7. Cross-cutting concerns
| Concern | Approach |
|---|---|
| Reproducibility | fixed seeds; every artifact built by a script; params in `results/tuned_params.json` |
| No leakage | split-aware loaders; test used only by final eval scripts; a test asserts no test ids in training data |
| Explainability | every ranked item carries a `breakdown` dict; frontend shows it |
| Performance | INT8 ONNX, numpy postings, top-K with heaps, candidate pools ≤ a few thousand docs |
| Errors | API returns `{error, detail}` with HTTP 4xx/5xx; frontend shows it; missing artifacts → clear "run script X first" message |
| Security / secrets | HF token only via env/CLI login; `.env` gitignored; API bound to localhost |
| Licensing | IL-TUR CC BY-NC-SA; credited in `DATA.md`; ZIP policy decided in P9 |
| Observability | per-stage timings in the explanation payload; simple `print` progress in scripts |

## 8. Risks at design level
- **Citations masked** in PCR text → citation graph impossible → fall back to judgment–statute bipartite graph and a kNN similarity graph (decided in P1).
- **Long documents** → chunking + caps; query reduction for BM25.
- **Neural training budget** → small encoder, short sequences, few epochs; distillation is cuttable.
- **Two-stack demo** (Python + Next.js) → frontend started early, contract fixed by `LLD.md` §9.
